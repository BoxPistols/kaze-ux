# サンプルデータの書き方

このリポジトリは public で、デモアプリのサンプルデータもそのまま公開される。
**サンプルには実在の企業名・製品名・型番を書かない。**

## なぜ

PR #68 で、モックデータに実在メーカー名と実在型番が入っているのが見つかった。
たとえば「電子部品 型番◯◯-◯◯◯◯ / △△ コンデンサ」「◯◯ ラックサーバー /
UPS △△」のように、実在の会社と実在の製品を並べた文字列がそのまま入っていた。

デモとしては具体的なほど説得力が出るが、公開されるサンプルに実在の名前を
使うと次の問題が出る。

- 取引先や導入実績と誤読される
- 商標の扱いが曖昧になる
- 一度公開すると Git 履歴・デプロイ済みの成果物・外部のキャッシュに残り、
  後から作業ツリーを直しても消えない（#74）

## どう書くか

**架空だとわかる名前を作る。** 実在しそうな一般名詞の組み合わせが扱いやすい。

| 書かない                    | 書く                               |
| --------------------------- | ---------------------------------- |
| 実在メーカー名 + 実在の型番 | `積層セラミックコンデンサ 2,000個` |
| 実在のサーバー製品名        | `ラックサーバー 2台 / UPS 1台`     |
| 実在の配達サービス名        | `KazeEats`                         |
| 実在の飲食チェーン名        | 架空の店名                         |

- **型番は「種類」に落とす。** 具体的な品番が要るなら、桁数と書式だけ真似た
  架空の値にする（追跡番号 `KL-20260320-0005` のように、このリポジトリの
  接頭辞を使うと架空だと伝わる）
- **人名は姓のみの一般的な日本語姓**にしてある。社名と同じ姓（本田・村田 等）が
  出るのは想定内で、検査もそれを誤検出しないようにしてある
- ロゴ・画像も同じ。実在ブランドのロゴを置かない

## 検査

```bash
pnpm check:brand
```

`scripts/check-brand-terms.mjs` が、よく知られた実在の企業名・製品名を
作業ツリー全体から探す。

走る場所は 3 つ。

| 段階               | 目的                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| `pnpm check:brand` | 手元でいつでも                                                        |
| **pre-push**       | **公開される前に止める**。push した時点で public な履歴に載ってしまう |
| CI (Quality Check) | PR と main への push の両方。管理者マージや Web UI 編集も拾う         |

区切りの違いは均してから照合するので、どの書き方でも引っかかる。
`Foo-Bar` / `Foo_Bar` / `Foo  Bar` / 改行での折り返しは、すべて `Foo Bar` として
扱われる。**元の不具合そのものがハイフン形（`〜-clone` / `〜-theme`）だった**ため、
ここは揃えてある。

意図的に残す場合は、同じ行に**通す語を書いた**コメントを付ける。

```ts
const LEGACY_KEY = 'ubereats-theme' // brand-check-allow: ubereats — 改名前キーの読み取り互換
```

**語を書かないと通らない。** 目印だけで行ごと通すと、その行は以後すべての
実在名に対する盲点になり、あとから別の名前を書いても気づけなくなる。

コメントを書けない形式（JSON 等）は、スクリプト内の `ALLOWED_OCCURRENCES` に
**理由付きで**追加する。`contains` で対象の行を絞ること（ファイル単位で通すと
そのファイル全体が盲点になる）。理由を書けないものは残さない。

### 検査の限界

- **型番そのものは検査していない。** パターンで拾おうとすると、架空の追跡番号
  など正当な値に当たる。誤検出が出るチェッカはすぐ無視されるようになり、
  本物の検出まで一緒に流されるので入れていない
- 一覧に無い実在名は当然すり抜ける。**検査は「二度目を止める」ためのもの**で、
  最初に気づくのは書く人とレビューの役目
- 画像そのもの（PNG / AVIF）は見ていない。`.svg` はテキストなので見る
- JSON が `\uXXXX` でエスケープされていると日本語の語は一致しない

### 一覧を増やすとき

社名が人の姓と同じもの（Honda / Murata / Suzuki 等）を**単体で足さない**。
このリポジトリのサンプルの連絡先には同じ姓の人物がいるため、必ず誤検出する。
会社を特定する形（`Honda Motor` / `村田製作所`）で足すこと。<!-- brand-check-allow: honda motor --><!-- brand-check-allow: 村田製作所 -->

この行自体が検査に引っかかるので、行末に許可マーカーを置いてある。
説明のために実在名を書く必要がある箇所は、こうして明示的に通す。

追加したら、`pnpm check:brand` が **0 件で通ること**と、その語を実際に仕込むと
**落ちること**の両方を確認する。
