# Kaze Design System — 設計思想

## 理念

> 規範は、検証されて初めて規範となる。

違反が検出されない規約は、遵守されているかどうかを誰も判定できない。
記述と実装の一致こそが、デザインシステムの信頼の基盤である。

## 使命

**表現の自由と、品質の下限を、同時に成立させる。**

意匠の正解を配る仕組みではない。いかなる見た目を選んでも満たすべき
最低条件のみを規定し、それが満たされていることを継続的に検証する。

## 価値基準

|                |                                                                          |
| -------------- | ------------------------------------------------------------------------ |
| **検証可能性** | 実測に基づく。反証を用意する。未達を明示する。数値で示す。例外を隠さない |
| **単一性**     | 生成物として配る。二重定義を持たない。鮮度を強制する。手作業を排する     |
| **中立性**     | 実装に依存しない。意匠を規定しない。移植を前提とする。拡張点を定義する   |

## 原則

### 1. 規範と強制手段は一体で定義する

止める仕組みを持たない規範は、規範として扱わない。強制の所在を規約と
同じ場所に記し、無い場合は「なし」と明示する。

### 2. 仕様は機械可読を第一とする

人向けの記述は、機械可読な定義から導出する。二つの記述が併存すれば
必ず乖離するため、単一の定義から生成し、生成物の鮮度を継続的に検証する。

### 3. 保証は下限に限定する

可読性・操作性・意味の伝達のみを共通の要件とする。色・書体・余白の
選択は各プロダクトの領分とする。

---

## 共通要件（原則 3 の具体）

| 要件                                   | 検証方法                                 |
| -------------------------------------- | ---------------------------------------- |
| 本文コントラスト 4.5:1                 | 実際に敷かれる面で測定（半透明は合成後） |
| 操作対象 24×24 以上                    | 描画寸法を測定（WCAG 2.2 SC 2.5.8）      |
| フォント 12px 以上 / ウェイト 400・700 | 実ビルドを描画して測定                   |
| 色はトークン参照                       | ハードコード値を検出                     |

色・書体・余白の**選択**は規定しない。

## 色の構造

塗り面と前景で別のトークンを持つ。面が異なれば必要な前景色も異なるため。

| スロット       | 用途                                          |
| -------------- | --------------------------------------------- |
| `main`         | 塗り面                                        |
| `contrastText` | `main` の面に乗る文字（実測で決定）           |
| `onLight`      | `light` の面に乗る文字                        |
| `textContrast` | 素の背景と `lighter` の面に乗る文字・アイコン |

`primary.main` をそのまま文字色に用いると、明るいセマンティック色は白地で
2.6:1 程度にとどまる。
