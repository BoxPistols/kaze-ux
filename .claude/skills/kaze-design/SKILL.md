# kaze-design

UI を新しく作るとき、既存の UI を直すときに読む。

**このスキルは見た目を決めない。** 色や形の正解は各プロダクトのもの。
ここが規定するのは、**どんな意匠を選んでも満たすべき下限**と、
**AI が無意識に出してしまう定型スタイルの排除**だけ。

> 規範は、検証されて初めて規範となる。

---

## 0. 最初にやること

**プロジェクトのトークンを探す。** 無ければ作る前に確認する。

```bash
# よくある置き場所
ls design-tokens/ tokens.json src/themes/ tailwind.config.* 2>/dev/null
grep -rn "^\s*--color-\|primary.*#" src/*.css src/**/theme* 2>/dev/null | head
```

| 見つかったもの     | 取る行動                                                       |
| ------------------ | -------------------------------------------------------------- |
| トークン定義がある | **それを使う。** 新しい色を発明しない                          |
| CSS 変数だけある   | 変数を参照する。値を直接書かない                               |
| 何も無い           | 色を 1 つずつ足す前に、最小のトークン組を先に決める（下記 §5） |

**やってはいけないのは、その場の判断で hex を書き足すこと。**
2 回目に別の値を書いた時点で、もう誰も正解が分からなくなる。

## 1. 例外を認めない下限

意匠が何であれ、これだけは満たす。**満たせない意匠は選ばない。**

| 要件                       | 基準                   | よくある破り方                       |
| -------------------------- | ---------------------- | ------------------------------------ |
| 本文のコントラスト         | 4.5:1                  | 淡い面の上のグレー文字               |
| 大きい文字・アイコン・境界 | 3:1                    | 細い罫線、薄いプレースホルダ         |
| 操作対象の寸法             | 24×24 以上             | アイコンだけのボタン、密なテーブル行 |
| フォントサイズ             | 12px 以上              | 注釈・キャプション・バッジ           |
| フォントウェイト           | 使う段を 2〜3 に絞る   | 400/500/600/700 を混在させる         |
| フォーカス                 | 必ず可視               | `outline: none` を置き去りにする     |
| 色以外の手がかり           | 状態は色だけで伝えない | 赤／緑だけのステータス               |

### コントラストは「実際に敷かれる面」で測る

**素の背景で測ると嘘になる。** 半透明を重ねた面、tint を敷いた面、
グラデーションの上——文字が実際に乗る面で測る。

```
❌ 白地で 4.6:1 だから大丈夫
✅ この文字が乗るのは alpha 12% の tint を白に重ねた面。そこで測ると 4.3:1 → 不足
```

塗り面の色をそのまま文字色に使わない。**面用と前景用は別の値**になる。
明るいブランド色は、白地に置くと 2〜3:1 しか出ないことが多い。

## 2. AI が出しがちな定型を出さない

以下は「間違い」ではないが、**AI が生成した見た目**として一目で分かる。
指示が無い限り出さない。

### 出さないもの

|                               | なぜ                                                     |
| ----------------------------- | -------------------------------------------------------- |
| カード上端のカラーバー        | 意味を持たない装飾。情報を足していない                   |
| 角丸 + 片側だけの太いボーダー | `rounded-lg border-l-4` の類。出自がもっとも透けて見える |
| 紫 → 青のグラデーション背景   | 出自が透けて見える最たるもの                             |
| すべての角を同じ半径で丸める  | 階層が消える。要素の役割が読めなくなる                   |
| 見出しに絵文字（✨🚀📊）      | 内容の重みを下げる                                       |
| 何でも中央寄せ                | 読み始めの位置が定まらない                               |
| 3 カラムの特徴カード          | 内容が 3 つでないのに 3 つにされる                       |
| 影を何段も重ねる              | 浮きの序列が崩れ、全部が浮いて見える                     |
| 全面ガラス（過度な blur）     | 背後が読めず、コントラストが落ちる                       |

### 代わりにやること

- **階層は太さと余白で作る。** 色数を増やさない
- **色は意味のあるところにだけ置く。** 装飾に使わない
- **角丸は役割ごとに変える。** 小さい部品ほど小さく
- **区別が要るなら、全周を細い線で囲むか面の色で示す。** 一辺だけ太くしない
- **余白は 1 つのスケールから取る。** 4px か 8px の倍数で通す
- **面は 2〜3 段まで。** 背景・カード・その上、で足りる

### 判断に迷ったら

**「この要素を消したら、情報は減るか？」** 減らないなら装飾。置かない。

## 3. 作るときの順序

1. **情報の順位を決める。** 何を最初に読ませるか。1 画面に主役は 1 つ
2. **骨格を決める。** 余白とグリッドだけで組み、色を付けずに成立させる
3. **意味の色だけ足す。** 状態・アクション・警告。装飾には足さない
4. **下限を測る。** §1 の表を実際の描画で確認する
5. **消す。** 情報が減らない要素を落とす

**色から始めない。** 骨格が成立していない画面は、色を足しても直らない。

---

## 4. プロダクトごとの拡張

### 上書きしてよいもの

- 色の値、書体、角丸のスケール、余白の刻み、アニメーションの長さ
- 部品の見た目（影の有無、境界線の太さ、密度）
- レイアウトの流儀（サイドバー / トップナビ）

### 上書きしてはいけないもの

- §1 の下限
- トークンを経由するという構造そのもの（値を直接書かない）
- 意味と色の対応（成功が赤、のような入れ替え）

### 拡張の作法

**トークンを足すときは、既存のスケールに沿わせる。** 中間値が欲しくなったら、
まずスケール自体が粗すぎないかを疑う。

**部品を足すときは、2 つ目の利用箇所が出てから共通化する。**
1 箇所しか無いものを先に抽象化すると、仕様が固まらないまま負債になる。

---

## 5. トークンが無いプロジェクトで最小構成から始める

最初に決めるのはこれだけ。**これ以上増やさない。**

```
色    背景 / 面 / 文字（主）/ 文字（副）/ 境界 / ブランド / 成功 / 警告 / 危険
      + それぞれの「面に乗せる文字色」
余白  4px 基準のスケール（4 8 12 16 24 32 48）
角丸  小・中・大の 3 段
文字  サイズ 5〜6 段、ウェイト 2 段
```

**「面の色」と「その面に乗る文字色」は必ずペアで決める。**
片方だけ決めると、後から面を変えたときに文字が読めなくなる。

ライトとダークの両方を最初に決める。**後から足すと、必ずどちらかが破綻する。**

---

## 6. 直すときは、同じ形が他に無いか探す

1 箇所直して終わりにしない。**同じ構造が別の場所にもある**ことが多い。

```bash
# 例: 固定幅のグリッドを直したなら、他の固定幅も探す
grep -rn "gridTemplateColumns.*px" src/ | grep -v "minmax"
```

直したあと、**自分の修正が別の経路に副作用を作っていないか**も確認する。

---

## 7. 検証

このリポジトリには下限を実測する仕組みがある。他プロジェクトへ持っていく
場合は [docs/adopt-the-scheme.md](../../../docs/adopt-the-scheme.md) を参照。

| コマンド           | 何を測るか                           |
| ------------------ | ------------------------------------ |
| `pnpm check:a11y`  | 描画したコントラストと操作対象の寸法 |
| `pnpm check:typo`  | 描画したフォントサイズとウェイト     |
| `pnpm check:rules` | 禁止パターンの違反数                 |

**緑を見ただけで信用しない。** 検査を入れたら一度壊して、赤くなることを
確認してから使う。
